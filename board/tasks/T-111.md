## Goal
An in-game perf meter: FPS, frame time, and an indication of where the bottleneck in the main loop is, CPU or GPU.

Godot 4.7.2 gives what is needed: `Engine.get_frames_per_second()`; `Performance.TIME_PROCESS` and `TIME_PHYSICS_PROCESS` for script/physics CPU time; `RenderingServer.viewport_set_measure_render_time(viewport_rid, true)` then `viewport_get_measured_render_time_cpu()` / `_gpu()` for render CPU and GPU time per frame; `Performance.RENDER_TOTAL_DRAW_CALLS_IN_FRAME` and object/primitive counts. Note `Engine.max_fps = 60` caps the frame, so judge the bottleneck by which side's time is closest to the frame budget (CPU = process + physics + render CPU on the main thread vs GPU time), not by FPS alone.

A small overlay in a corner: FPS (with 1 % low over a few seconds), frame ms, CPU ms split (process / physics / render), GPU ms, draw calls, and a clear label: "GPU-bound", "CPU-bound (scripts/physics/render)" or "under budget (capped)". Toggle with a rebindable key shown in Controls (like the net overlay on `), off by default, cheap when off.

## Done when
- The overlay shows live FPS, frame ms, CPU split, GPU ms, draw calls and the bottleneck label; the toggle key is rebindable and listed in Controls.
- Sanity-checked on this Mac in the village and the haunted forest: e.g. a forced heavy GPU load reads GPU-bound and a busy-loop script reads CPU-bound.
- A headless test checks the classification logic from fake timings and that the meter costs nothing when hidden.
- docs/ui.md describes it and its limits (headless has no GPU times; timing granularity).
